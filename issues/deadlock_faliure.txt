the 0.32 percent fail rate is due to the following reason 

0. Suppose Bob already has an old resting BUY 2 @100, committed earlier, so his row is not locked.

1. Alice's transaction (SELL 5 @100) runs the reserve step and locks Alice's row.
2. Bob's new transaction (BUY 3 @101) runs the reserve step and locks Bob's row. This happens before the book mutex, so it can be at any moment.
3. Alice takes the book mutex and matches Bob's old resting BUY for 2. The remaining 3 rest in the book, and the mutex is released.
4. Bob's new order takes the mutex and matches Alice's resting 3.
5. Alice's transaction runs settle_trades and needs Bob's row for the first trade. Bob's new transaction holds it, so she waits.
6. Bob's transaction runs settle_trades and needs Alice's row for the second trade. Alice's transaction holds it, so he waits.
